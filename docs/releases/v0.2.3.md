# Draugr Time v0.2.3 — shared Week grid and responsive history reads

Week now uses one shared local-clock grid with compact clickable dates,
colored tag chips, interval tooltips and cross-day tag highlighting. Today and
its current-time marker are highlighted; future time stays blank. The default
hour range follows observed activity. Daily totals and relative bars make busy
days easier to compare, and all seven rows fit with the legend at 900×600.

- Reports and JSON history export release storage between event prefixes;
  aggregation runs outside the storage mutex. The desktop retains its last
  status during tracker contention instead of blocking the UI, including macOS
  main-thread sampling.
- CSV/JSON export replaces a destination confirmed in the save dialog using a
  synced temporary file beside it. Failed writes preserve the previous file.
- Legacy AFK queries stop at the global first computer observation, matching
  the existing Day runtime and reports without constructing reversed intervals.
- Overview hour labels follow real local-hour timestamps on 23/25-hour days.
  Week aligns local clock hours across days; repeated DST hours share a column,
  while exact UTC intervals and numeric totals retain their actual durations.
- Refreshing Week preserves the custom date range entered in Reports.
- Concurrent metadata/history edits reject an in-progress report/export with a
  localized retry message rather than producing mixed edits.

All tracking data remains local. No database migration is needed. The app uses
its existing tempfile dependency directly for safe export replacement. Each
platform archive contains the desktop app and draugr-time-cli.

## Validation and limitations

Local cargo fmt --check, cargo clippy --all-targets -- -D warnings and cargo test
passed: 184 tests, 0 failures, 7 environment-dependent tests ignored. The separate
serial native rendering check passed for eight languages and both themes at
900×600. Regression tests cover export replacement and cleanup, history-prefix
parity, concurrent edits, AFK parity, DST hour labels, Week interactions and cache
invalidation. GitHub CI checks Linux, Windows and macOS before publishing assets.

A native smoke launch could not connect to a Wayland compositor in the local
sandbox. Real window/tray interactions, recording during dense-week loading and
save-dialog replacement still need manual verification on Windows/macOS and
Linux X11/Wayland. Week's minute bands approximate subminute visual detail;
reports and tooltip durations remain exact. D-Bus theme polling, thread joining
and the minute-cell color representation are unchanged. See docs/m7.md.
