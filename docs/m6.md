# M6 — auto-tagging and local translations

Rules works while the embedded tracker is running. Create a tag in Day/Tags,
then open Rules, choose New rule, a field (application executable, window title,
or URL), regex, target tag and integer priority. Regex matching is case sensitive
unless the expression uses a flag such as `(?i)`. Higher priority wins;
the oldest rule wins a tie. Rules can be saved, selected, changed, disabled and
deleted. Archiving a target tag prevents future automatic assignment.

The preview updates while editing and initially covers the selected day and its
six preceding local days. Start/end dates are inclusive; they are converted to
UTC millisecond bounds before querying. The preview includes the draft alongside
saved rules and shows newly taggable duration, interval count and up to five
sample matches. Apply to history previews **saved enabled rules**, then asks for
confirmation. Queries retain the existing 100,000-event safety limit; choose a
shorter date range if the limit is reached. Confirmation fails safely if the result changed; preview again.
Undo tag action / Ctrl or Cmd+Z removes only that application's inserted ranges
and preserves newer unrelated edits. Undo is available only in this process and
is refused if an affected applied range was edited afterward.

Automatic assignment covers observed awake, unlocked active time and preserves
existing tags. AFK, sleep, off, manual pause and gaps are never counted as work.
Changing rules does not rewrite previously assigned tags. URL rules operate on
existing local `web` observations; browser-extension capture remains M9.

Settings offers English, Русский, Deutsch, Français, Español, Português,
简体中文 and 日本語. System default follows OS language (Linux locale, Windows
UI language, macOS preferred language), with English fallback for unsupported
languages, including Traditional Chinese. Selection survives restart; choosing
System default redetects the OS language. Translations are bundled in
`app/translations.json`; no downloaded assets or network services are used.
Dates, compact duration units, dialogs, status labels and tray menus are localized.
Names/notes/titles entered by users and low-level OS/library diagnostic details
are retained verbatim. Add a translation key to every catalog with the same named
parameters; catalog tests enforce coverage and parameter parity.

## Verification

Local checks on 2026-10-14: `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, `cargo test` and the serial native
rendering check passed. Real Linux/Wayland smoke with German locale and 5,000
fixture events passed; maximum timeline geometry build was 2.16 ms in the debug
build. This is a fixture check, not a performance guarantee on other machines.


Tests were written before the corresponding implementation. Core tests cover
app/title/URL regexes, priority and ties, disabled/archived rules, invalid and
complex drafts, active-time boundaries, clipped manual overlaps, preview/apply
parity, transactional stale confirmations, selective undo and migration from v3.
A MockWatcher test covers automatic recording, pause/resume and missing samples,
including merged continuous automatic tags. The editor test exercises draft
preview, save, confirmation, application and undo. A 5,000-event rule fixture
checks aggregation without losing duration. Language tests cover locale parsing,
override, persistence, return to system, English fallback, catalog coverage,
parameter parity and zero/one/many abbreviated durations.

Run the serial native Iced rendering check (no graphical session required):

```sh
cargo test -p draugr-time native_widgets_render_every_language_screen_and_dialog -- --ignored --test-threads=1
```

It builds/draws all six current screens in all eight languages, both themes and
900×600 layout, and lays out a tag dialog. This checks native widget construction
and horizontal layout bounds; it does not establish translation fluency or real
platform menu/font behavior.

Manual verification on **Windows, macOS, Linux X11 and Wayland**:

1. Change each language; inspect Day, Tags, Rules, Settings, all tag/overlap/delete
   dialogs and the away prompt at 900×600 and larger sizes. Verify CJK glyphs,
   long labels, selection, keyboard controls and light/dark themes.
2. Open the actual tray menu while the window is open, change language, then
   close/reopen the window. Verify updated menus and state labels.
3. Restart after a language override, return to System default, change OS display
   language, relaunch and check English fallback for an unsupported language.
4. Match an app/title rule, idle, lock, sleep, pause and return. Confirm tags cover
   only the observed active intervals. Disable the rule and verify new intervals
   stop being tagged.
5. Confirm an historical application and undo it while tracking continues. Check
   newer history survives; editing an applied interval must make undo refuse.
6. Review translations with fluent speakers, especially Portuguese regional
   wording. Minimal Linux installs need a local CJK font (for example Noto CJK).

Windows and macOS checks require their real desktop sessions. Real pointer,
tray integration and OS language changes are not covered by the headless test.
