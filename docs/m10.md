# M10 — Release 1.0

Release archives contain the desktop app and platform icons. Windows keeps the
separate console `draugr-time-cli.exe`; Linux/macOS accept `draugr-time report`,
`export`, `import`, `status` and `--help` before any GUI/tray initialization.
The existing standalone Unix CLI still builds for compatibility.

## First launch

The two-screen welcome explains collection and the actual local data directory,
then offers permission/setup hints and **Start recording**. Nothing is recorded
until that button is pressed. Completing onboarding persists `settings.json`;
later normal launches start tracking automatically. Existing data and older
folder/language/startup preferences are preserved.

Windows embeds the logo/version resource in both executables. macOS archives
include `Draugr Time.app` with Info.plist, the executable and an `.icns` icon,
plus a top-level executable for terminal use. Linux archives include a `.desktop`
file and hicolor icon. Onboarding/Settings → **Add to application menu** installs
an entry pointing at the current executable, correctly quoting paths with spaces
and special characters. Keep the extracted directory in its permanent location
before adding the entry or enabling startup at login. The runtime application ID
matches the desktop entry, so Wayland docks can associate its icon.

On Linux, **Install GNOME bridge** / **Install KDE bridge** copies bundled assets
into the user's normal desktop discovery directory. GNOME then needs logout/login
and enabling Draugr Time Watcher in Extensions. KDE needs enabling it in System
Settings → Window Management → KWin Scripts. X11, Sway and Hyprland need no bridge.
On macOS, **Open Accessibility settings** opens the relevant System Settings page.
Missing permissions and unsupported backends remain visible on Day/Settings.

## Minimal privacy settings

- Exclusions accept exact application IDs or executable paths separated by
  semicolons (ASCII case insensitive). Excluded application/title observations
  never reach storage, rules or current-activity status. Independent computer
  active/away totals remain. Existing history is unchanged.
- The optional recording schedule uses local wall-clock HH:MM times and either
  weekdays or every day. Start is inclusive and end exclusive; same-day windows
  only. DST follows the OS local clock; stored timestamps remain UTC milliseconds.
  Outside the schedule, the tracker records a pause reason and no app/idle
  observations. Scheduled gaps do not become working time after recording resumes.
  Disable or change the schedule to record outside its hours; Resume alone does
  not bypass it. Manual Pause remains in force when a schedule opens.
- Delete acts on the Day selection or displayed local day. Confirmation captures
  and displays the interval. Event/tag-range intersections are removed atomically;
  pieces outside the interval remain. Live tails and UI undo/caches are invalidated
  so they cannot restore deleted history. Tags and rules themselves remain.

Settings writes are atomic; malformed privacy settings prevent tracking startup
instead of silently enabling collection. Migration 005 retains the original creation precedence of split tag ranges so
range deletion does not change overlap assignments outside its boundaries.

## Verification

Tests cover onboarding persistence, application list/time parsing, schedule
validation and exact boundaries, MockWatcher exclusion before storage/status,
scheduled pause/resume without invented work, every range-deletion overlap shape,
buffered tails, CLI operation without a graphical session, icon file structures,
macOS bundle contents and Linux desktop-entry quoting.

Before certifying fresh-archive behavior on a real platform:

1. Windows: extract the ZIP, check Explorer/taskbar/window/tray icons, launch the
   desktop app, complete onboarding, switch applications and inspect Day. Run
   `draugr-time-cli.exe --help` in a terminal. Verify executable-resource metadata.
2. macOS: extract, move the `.app` to Applications, launch it, grant Accessibility
   and inspect Day, menu bar and Finder icons. Check built-in CLI from a terminal.
   The app is ad-hoc signed, not Developer ID signed/notarized; downloaded archives
   may require Privacy & Security → Open Anyway.
3. Linux X11/GNOME/KDE/Sway/Hyprland: extract to a permanent folder, launch the app,
   install the application-menu entry and relevant bridge through onboarding,
   enable the bridge using desktop controls, then verify Day, tray and dock icons.
4. On every OS: exclude a sensitive app and verify exported JSON/status; exercise
   a short schedule, manual pause and schedule reopening; delete a selection and
   confirm both outside portions remain. Check local midnight/DST behavior.
5. Check both themes, keyboard access, narrow windows and supported languages.

CI smoke tests/builds cannot replace real OS permission/login and fresh-archive
walkthroughs. Installers belong to M11; backups and title masking belong to M12.

Local verification on 2026-10-16 (Linux/Wayland): fmt and strict clippy passed;
all Rust tests passed; six Python distribution/skeleton checks passed. Native
fixture smoke (5,000 events, maximum canvas build 0.52 ms), two-screen onboarding
with persisted completion, embedded recording, and tray close/reopen lifecycle
checks passed with isolated data and session buses. These use mock activity and
do not certify real compositor permission behavior.
