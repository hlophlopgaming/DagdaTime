# M7 — overview, reports and local CLI

Overview is separate from the editing Day view. The inner donut ring groups
active time by top-level project; the outer ring shows applications in each
project. Untagged time and unknown applications remain visible. Each millisecond
belongs to one project/application pair; the highest tag-range ID wins overlaps.
Inactive time is excluded from the donut, and stays visible on the compact
computer/activity timeline. Missing window observations have a diagnostic stripe.

Click an inner project sector, an outer application sector or a legend control
to highlight its timeline intervals. Hover shows duration and percent. Up/Down
select project and application entries using the keyboard; E expands/collapses small sectors
and Esc clears highlighting. Sectors smaller than 2% of total active time become
Other inside their own project; their names are listed and expansion restores
individual sectors. The legend stacks under the chart in narrow windows.

Week uses Monday–Sunday, shows seven compact local-day timelines and project
totals; click a day's date/total to open Day. Reports offers day/week/month/custom
inclusive calendar dates, tag/application/document grouping, top-level project
filtering, proportional bars and a horizontally scrollable tags × days timesheet.
Load report refreshes the selected history. Reports exports CSV or a restorable
JSON archive and copies CSV text to the clipboard. Choose a new filename when
exporting: existing destinations are not overwritten. Settings → Data folder
includes import for ActivityWatch or Draugr JSON.

The CLI is a console binary separate from the desktop executable:

```sh
cargo run -p draugr-time --bin draugr-time-cli --offline -- --help
# With built binaries:
draugr-time-cli status --json
draugr-time-cli report --from 2026-10-01 --to 2026-10-07 --group tag --json
draugr-time-cli report --from 2026-10-01 --to 2026-10-07 --group application --format csv
draugr-time-cli export --from 2026-10-01 --to 2026-10-07 > history.json
draugr-time-cli --data-dir /absolute/path/to/new-folder import history.json
draugr-time-cli import activitywatch-export.json
```

Calendar dates follow the machine's local timezone and include the end date.
Numeric from/to values are Unix UTC milliseconds and use an exclusive end.
JSON and CSV machine-readable timestamps are UTC milliseconds. `--tag ID`
filters reports by a top-level project ID. JSON export is a history archive;
CSV export is a grouped active-time report and cannot be imported as history.
Read commands require an existing database; import can create a new data folder.
Output goes to stdout; errors go to stderr with exit code 1. Live status requires
a running local tracker and the selected folder's api-token.

Imports validate first and insert atomically, remapping tag and event IDs.
Existing history is never replaced. Overlapping events in one destination bucket,
multiple overlapping host histories and unknown ActivityWatch bucket types are
rejected. Export only currentwindow/afkstatus/web.tab.current buckets from
ActivityWatch; use a separate data folder to inspect conflicting history. Rules,
preferences and undo history are not part of a history archive.

GUI ranges are limited to 366 days, and the existing query cap is 100,000 events.
Choose shorter ranges if the application reports that limit. Reports are refreshed
explicitly; the Overview follows live Day data. The full Day summaries retain
their original wall-clock shares; overview/report shares use observed active time.

## Verification

Tests were added before implementation. Core coverage includes hierarchy and
unrelated overlaps, unknown/untagged time, interval clipping, cross-midnight
additivity, inactive states, diagnostics, 5,000 events, JSON round-trip, CSV quoting,
ActivityWatch conversion and atomic validation/rollback. CLI integration tests
run with DISPLAY/WAYLAND_DISPLAY removed and cover help, report/export parity,
import, invalid arguments/failure codes and 23/25-hour Europe/Berlin DST days.
Native canvas tests dispatch real mouse events; desktop tests cover keyboard
highlighting, small-slice expansion, stale loads and report-cache cleanup.

Required workspace checks: cargo fmt --check, cargo clippy --all-targets --
-D warnings, cargo test. The serial native widget check renders all seven screens
with eight languages, light/dark themes and a 900×600 viewport:

```sh
cargo test -p draugr-time --bin draugr-time native_widgets_render_every_language_screen_and_dialog -- --ignored --test-threads=1
cargo run -p draugr-time --offline -- --smoke-test --screen Overview
cargo run -p draugr-time --offline -- --smoke-test --screen Week
```

Manual checks on Windows/macOS/Linux X11/Wayland:

1. Open Overview with real history in both themes; hover/click both rings and
   legend controls, use Up/Down/E/Esc, and verify corresponding timeline highlights.
2. Resize to a narrow window, scroll the legend, expand Other and inspect member
   names; check fonts, translated labels and empty days.
3. Open Week, navigate dates and click a day; verify active totals agree with Day.
4. Run grouped reports and timesheets across midnight and DST; filter a project,
   copy/export and compare with CLI output for the same local calendar range.
5. Use the platform file picker to export to a new file; import an archive into
   an isolated data folder. Check a conflicting import leaves existing history intact.
6. Hide/reopen the window while a report loads, then reload; stale results must not
   restore old data. Verify Windows/macOS console status/report/export/import using
   draugr-time-cli, without opening the desktop window.

Headless native drawing tests do not establish actual file-picker, menu, font or
assistive-technology behavior. Windows/macOS require their own desktop sessions.

### 2026-10-15 — Week and export follow-up

Week now has one shared clock grid, compact clickable dates, per-day totals and
relative bars, colored tag chips, cross-day tag highlighting and interval hover
details. The initial hour range follows observed active time and includes now on
the current week; empty weeks show the full day. Today is marked and future time
is blank. The Reports date fields survive Week navigation. DST hour labels use
actual local hours; on the shared Week axis, repeated wall hours share a column,
while totals and tooltip durations use exact UTC intervals.

Report/export reads release storage between event prefixes. UI status and macOS
sampling avoid waiting for the tracker's control mutex. JSON/CSV export can
replace a confirmed destination using a synced temporary file in the same folder.
Concurrent metadata/history edits reject the read with a retry message; the old
export file is preserved.

Verification: workspace fmt, clippy and tests; dedicated native canvas tests for
clicks, hover, cropping, future intervals and cache invalidation; core/Shared
report and archive parity across 8,192-event boundaries; concurrent-edit rejection;
AFK parity with loaded Day; export replacement/cleanup; real clock labels on
23/25-hour days. The serial native rendering check covers eight languages and
both themes at 900×600. To save Week previews through the software renderer:

```sh
mkdir -p /tmp/draugr-week-preview
DRAUGR_TIME_SCREENSHOT_DIR=/tmp/draugr-week-preview cargo test -p draugr-time --bin draugr-time native_widgets_render_every_language_screen_and_dialog -- --ignored --test-threads=1
```

Manual checks still needed on Windows/macOS and Linux X11/Wayland: open a dense
week while recording and confirm that the window/tray stays responsive and
